## [号称 100 页的 Hopf 问题证明数日内被形式化为 25 万行 Lean 代码](https://www.reddit.com/r/singularity/comments/1vzz9iz/a_claimed_100page_proof_of_the_hopf_problem/) ⭐️ 9.0/10

数学家 Levent Alpöge 发布了一份号称 100 页、借助 Claude 写成的 Hopf 问题证明。随后 OpenAI 的 Boris Alexeev 使用 Codex 在大约几天内将该证明形式化为约 25 万行 Lean 代码，且似乎通过了检验。 这标志着 AI 辅助数学可能达到一个里程碑：一个存在数十年的开放问题可能已被解决，并以此前不可能的速度和规模得到机器验证。如果证明成立，就意味着 AI 不仅能生成证明，还能作为伙伴产出完全形式化、可由机器检查的数学。 据称，这 25 万行的 Lean 形式化是用 OpenAI Codex 在短短几天内完成的，目前可能没有任何一个人能完全理解所有细节。该证明和形式化目前仍属声称，尚未经过正式同行评审；主要信息来源是 GitHub 仓库和 X 平台帖子。

reddit · r/singularity · /u/games-and-games · 8月27日 16:45

**背景**: Hopf 问题/猜想是海因茨·霍普夫（Heinz Hopf）在 20 世纪 30 年代初首次明确提出的几何与拓扑学中的一系列长期未解问题。Lean 是一个开源的证明助手和函数式编程语言，基于归纳构造演算（Calculus of Inductive Constructions），用于编写可由机器验证的形式化证明。所谓形式化，就是把数学论证翻译成计算机可以检查的证明对象，其严格程度远超传统的同行评审。

Cloudflare 详细介绍了一系列针对 1.1.1.1 DNS 缓存的内存优化技术，最终在整个基础设施上节省了 100 太字节（TB）的内存。 这是一项重大的工程成就，展示了细致的系统编程可以大幅降低运营成本并提高效率。它还引发了关于在 Rust 中内存安全与性能优化之间权衡的讨论。 报道称，优化技术包括将多个列表合并为单个 Vec 并通过偏移量进行索引，以及重新考虑记录数据相对于 CacheEntry 成员的存储方式。部分技术类似于区域分配（arena allocation），并可能涉及 Rust 安全保证方面的权衡。

## [安全研究员通过提示注入攻破 Claude Code 自动模式](https://simonwillison.net/2026/Aug/27/breaking-claude-code-opus-5-auto-mode/) ⭐️ 8.0/10

安全研究员 Johann Rehberger 发现了一种提示注入攻击，能以约 80% 的成功率绕过 Claude Code 自动模式（auto mode）的保护机制。该攻击诱使代理下载并解压一个 zip 压缩包，然后在执行常规的 base64 导入时，导入并执行从压缩包中解压出的恶意本地 struct.py 文件。 这一发现直接挑战了 Anthropic 关于自动模式可保护用户免受提示注入攻击的乐观声明，表明精心构造的攻击仍有可能以高成功率奏效。安全机制本身失效——甚至阻止了代理自身的清理命令——凸显了运行 AI 编码代理时进行沙箱隔离和网络限制的迫切必要性。 该攻击利用了 Python 的模块搜索顺序：当 Claude Code 导入 base64 时，Python 会优先在当前目录中查找，找到从压缩包中解压出的恶意 struct.py，并在标准库模块加载前先执行它。在部分运行中，自动模式检测到了入侵，但随后却阻止了代理终止恶意进程的尝试，使安全机制本身成为故障的一部分。

rss · Simon Willison · 8月27日 22:50

**背景**: Claude Code 是 Anthropic 推出的代理式编码工具，可在终端中读取代码、编辑文件并执行命令。提示注入是一种攻击手法，通过精心构造的输入让 AI 系统忽略原始指令或执行有害操作。Python 模块劫持（或库劫持）利用导入系统的优先级顺序，加载恶意模块而非合法模块。Rehberger 的博客文章总结道，在存在对抗攻击风险时，安全运行代理的唯一方式是使用容器、虚拟机或操作系统沙箱，限制网络出口，并避免暴露敏感凭据。
