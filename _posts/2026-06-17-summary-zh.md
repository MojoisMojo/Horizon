## [RFC 10008 正式引入 HTTP QUERY 方法](https://www.rfc-editor.org/info/rfc10008/) ⭐️ 8.0/10

IETF 发布了 RFC 10008，定义了 HTTP QUERY 方法。它允许请求携带请求体，并且是安全且幂等的，解决了长期以来需要在不产生副作用的情况下发送复杂数据检索请求的问题。 这一新方法使得需要请求体的数据查询可以享受缓存和自动重试机制，而此前只能使用 POST（有副作用风险）或将所有内容编码到 URL 中（受限且不安全）。它弥补了 HTTP 语义中的一个空白，尤其有利于 GraphQL 等 API。 QUERY 方法被定义为安全的（不改变服务器状态）和幂等的（相同请求具有相同效果）。但缓存实现必须考虑请求体，若不谨慎处理可能导致无限制的缓存键。IETF 工作组由于历史互操作性问题，否决了在 GET 中允许请求体的方案。

hackernews · schappim · 6月17日 10:51 · [社区讨论](https://news.ycombinator.com/item?id=48568502)

**背景**: HTTP 是 Web 的基础协议。传统上，GET 用于获取数据但不能包含请求体，数据必须通过 URL 传递，而 URL 有长度限制且完全可见。POST 可以携带请求体但不是幂等的，重复请求可能引发副作用，因此不适合缓存或安全重试。QUERY 方法结合了 GET 的安全性和幂等性，并支持发送请求体，标准化了开发者长期需要的一种模式。
