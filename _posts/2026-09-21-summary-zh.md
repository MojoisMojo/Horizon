### [Proxifield：通过语义邻近实现去中心化多智能体通信](https://arxiv.org/abs/2609.20889) ⭐️ 8.0/10

Proxifield 是一种新的去中心化多智能体通信协议，通过语义邻近构建稀疏通信图，从而提升复杂环境下的协作效率。该协议在推理时利用四种路由信号：直接地址、信息需求、计划对齐和信息互补性，无需模型训练或集中式规划。在无人机搜救和 HiddenBench 集体推理基准测试中，Proxifield 在模型规模扩大时表现优于两个基线协议，包括在团队规模达到 50 时任务奖励优势达到 59.5%。此外，Proxifield 在面对永久性智能体故障时表现出更高的鲁棒性，保留了 73.6% 的无故障任务奖励，远高于 Shared Context 的 58.3% 和 Star 的 38.8%。

rss · arXiv Multi-Agent Systems · 9月21日 04:00

**「多智能体通信的背景」** 多智能体通信是随着大型语言模型（LLM）能力的提升而兴起的研究领域，传统协议常采用刚性结构，导致协调瓶颈并影响系统扩展性。近年来，研究者提出了多种基于 LLM 的多智能体通信框架，如 LLM Coordination 框架，它通过动态规划、检索和执行等机制实现多智能体的协调。此外，一些研究尝试引入认知架构来提升多智能体协作的灵活性和可扩展性。

**「Proxifield 提高多智能体系统的可扩展性和容错性」** Proxifield 在 Drone Search and Rescue 和 HiddenBench 领域中表现出显著的性能优势，特别是在团队规模扩大时，其任务奖励比 Star 协议高出 53.0%（N=25）和 59.5%（N=50），同时比 Shared Context 协议更具鲁棒性，即使在永久智能体故障的情况下仍能保留 73.6% 的任务奖励。

### [基于贝叶斯信念层的 LLM 代理可控意见动态研究](https://arxiv.org/abs/2609.21997) ⭐️ 8.0/10

该论文提出了一种名为贝叶斯纪事代理（Bayesian Chronicle Agents, BCA）的框架，用于在 LLM 代理中实现可控且透明的意见动态。通过引入一个分离‘信念内容’与‘表达方式’的最小信念层，每个立场以概率形式表示，并在每次听到陈述后通过一次贝叶斯更新。研究通过调整单个先验强度参数κ，实现了三种意见动态模式：共识、持续分歧和坚定少数派影响。实验结果显示，持续分歧模式与 Friedkin-Johnsen（FJ）意见动态模型的闭式固定点匹配，相关系数达到 0.93 至 0.99。此外，该方法还支持对指定κ值的恢复，并在所有四种模型中实现了完美的排名恢复，使模拟过程可审计，暴露出模型间的系统性立场偏差。

rss · arXiv Multi-Agent Systems · 9月21日 04:00

**「贝叶斯信念层与可控意见动态」** 该研究提出了一种名为贝叶斯时间线代理（Bayesian Chronicle Agents, BCA）的最小信念层，用于区分代理的信念内容和其表达方式。每个立场都以概率形式表示，并在每次听到陈述后通过一次贝叶斯步骤进行更新。一个单一的先验强度参数 κ 用于编码顽固性，其作用基于 Friedkin–Johnsen（FJ）意见动态模型中的角色。

**「BCA 对 LLM 代理意见动态的可控制性和透明性提升」** 该研究通过引入贝叶斯信念层，使 LLM 代理在社交模拟中的意见动态变得可控制和透明，能够实现共识、持续分歧和坚定少数派影响三种典型模式的切换，且在语言往返过程中仍能准确恢复指定的信念参数。

### [Loopjacking: 人类在环的审批被滥用的新安全漏洞](https://arxiv.org/abs/2609.21081) ⭐️ 8.0/10

一项新研究揭示了 AI 代理系统中的安全漏洞，称为 Loopjacking。该漏洞利用人类在环的审批机制，使审批者误以为执行操作 A，而系统实际执行操作 B，从而威胁系统完整性。研究者在多个已发布的代理产品中验证了这一攻击方法，包括七种 Agno AgentOS 版本和十二种 LangGraph Agent Server 版本。OpenClaw 2026.2.23 版本中存在表示不匹配问题，但在 2026.2.24 版本中被拒绝。OpenAI Agents SDK 0.22.0 和 0.22.2 版本通过精确的调用绑定和防止未经授权的待处理状态突变，有效阻止了这些攻击。研究强调了完整审批渲染和精确执行时比较的重要性。

rss · arXiv Multi-Agent Systems · 9月21日 04:00

**「背景」** 人类在环的审批机制通常被视为 AI 代理执行关键操作的最后一道安全防线。该机制的有效性依赖于审批过程中展示的操作与最终执行的操作一致。然而，研究发现某些系统中存在漏洞，使得审批者批准的操作与实际执行的操作不一致，从而导致安全风险。

**「影响」** Loopjacking 漏洞可能导致 AI 代理系统在关键操作中执行与审批者意图不符的操作，从而威胁系统安全性和可靠性，特别是在涉及敏感数据或高风险决策的应用场景中。
